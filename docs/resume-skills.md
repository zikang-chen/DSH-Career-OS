# 简历优化 Skill 库（把杂乱经历包装成 JD 定向简历）

> 方法论来自行业通行做法（Google XYZ 公式、STAR、ATS 关键词对齐、一页原则），
> **不是实证研究**，也不承诺效果。工具 `career_resume_skill` 会按你的要点做确定性诊断。

## 核心原则（先立规矩，再谈技巧）

1. **不编造**：只重组、改写措辞、调整顺序；数字没有就是没有，列缺口而不是编数据。
2. **一岗一版**：不同 JD 用不同措辞与排序，但事实不变。
3. **可验证**：每条要点尽量能被追问（你做了什么、怎么衡量、结果多少）。

## 8 个 Skill

| Skill | 何时用 | 怎么做 | 常见坑 |
| --- | --- | --- | --- |
| **XYZ 成果公式** | 要点只有职责、看不出结果 | 「做成了什么 X → 用什么指标 Y 衡量 → 怎么做 Z」 | 只写职责，不写结果 |
| **STAR 结构** | 项目/实习零散，说不清个人贡献 | 背景—任务—**你的**动作—结果 | 把团队成果写成个人成果 |
| **量化优先** | 要点没有任何数字 | 规模/效率/增长/成本/准确率前置 | **编数字**（绝对禁止） |
| **强动词开头** | 以「负责/参与/协助」开头 | 换主导/搭建/推动/设计/验证 | 把「参与」夸成「主导」 |
| **JD 关键词对齐** | 一份简历投所有岗 | 把 JD 核心词映射到真实经历措辞 | 不具备硬凑关键词 |
| **科研/校园 → 岗位语言** | 学术经历与岗位语言不通 | 问题—方案—可验证结果—业务含义；社团/副业→运营/转化/复购 | 术语堆砌、不落地 |
| **精简与一页原则** | 要点过多、单条太长 | 每段 ≤3-4 条，单条 ≤2 行，删无关细节 | 塞满当「显得厉害」 |
| **缺口诚实表达** | JD 要求你没有的 | 明确列缺口 + 补强计划 | 用模糊话术假装具备 |

## 用法

对话里直接说：

```
用简历 skill 检查一下我的要点，目标是腾讯产品经理
```

或指定要点：

```
帮我看看这几条怎么改：
负责用户增长相关工作
参与了短视频推荐项目
```

工具会返回：

- `skills`：适用的方法论（含 before/after 示例）
- `perBullet`：每条要点的诊断（缺量化 / 弱动词 / 看不出结果 / 太长）
- `jdCoverage`：JD 关键词覆盖了哪些、缺哪些
- `summary`：需要补量化几条、弱动词几条、缺哪些关键词

`career_prep_resume`（为岗位准备简历）也会自动带上 `skillAdvice`。

## 一条完整示例（诚实版）

原要点：`负责用户增长相关工作`

诊断：弱动词 + 缺量化 + 看不出结果

改法（只有你真有数据才填）：
> 主导新用户首周留存优化：通过 X 手段把次留从 **a%** 提到 **b%**，覆盖 **N** 万用户

如果你没有 a/b/N，就写成待补强，面试前一并补测，不要编。

## 与其它工具的关系

- `career_resume_quality`：查「有没有硬伤」（缺联系方式、时间倒挂、技能无依据）
- `career_resume_skill`（本文）：查「写得好不好、够不够对口」
- `career_prep_resume`：为某岗位挑经历 + 出缺口 + 附 skill 建议
- `career_resume_build`：按建议生成 LaTeX/文本版本
