# CareerOS 本轮产品结构改造

## 为什么重做

用户反馈界面与功能逻辑仍混乱。此前增加功能入口和流程按钮没有解决主次；本轮不增加新页面，重排现有产品结构。

## 页面职责

| 区域 | 用户任务 | 次级能力 |
|---|---|---|
| 总览 | 今天优先处理什么 | 计划与统计 |
| 找岗位 | 搜索、筛选、比较岗位 | 公司/行业背景 |
| 我的投递 | 跟进具体岗位与下一步 | 面试准备、冻结材料和漏斗 |
| 我的材料 | 真实经历、定向简历、参考资料 | 知识库归档和OCR证据 |
| 设置 | 数据源登录、接口、系统 | 调试与监控 |

## 岗位页面

默认先列表与筛选，不再先展示两个大采集表单。添加岗位统一折叠于列表后。
卡片信息：岗位标题→公司→地点/薪酬/招聘类型→硬条件→一句要求摘要→来源与截止。
缺值显示未知，不把缺JD的高匹配分当结论。
详情信息：来源状态/硬条件→职责/要求→准备简历、JD面试准备、加入投递。技术历史和维护收起。
已有投递点击定位该岗位投递，不重复建立收藏。普通导航清理旧岗位上下文，任务内跳转明确带岗位ID。

## 产品复审修复

- 首页“改简历”进入工作室，而不是跳到画像表单。
- 取消全局重复五步骤按钮，只有选定岗位时出现简洁的上下文返回条。
- 我的投递漏斗与网申卡默认折叠，减少压住主列表。
- 投递详情可继续看岗位、准备草稿和面试；说明已提交快照不可被新简历覆盖。
- 面试页带jobId筛本岗位真实样本，不再拿全库面经冒充此岗位调研。
- 知识库公司可模糊检索，完整度改中文，不让用户读内部枚举。

## 验证与未验证

本轮356项离线测试通过（含4项岗位页面任务/防重测试），构建和语法检查通过。两轮独立产品/UX代码走查，已修实质问题。
没有当前已认证DSH GUI控制工具，未完成真实页面点击、亮暗主题及窄屏视觉验收，不能声称用户已看到/觉得好用。需要用户刷新现有GUI查看本轮实际版本后继续按具体问题调整。

筛选边界：当前城市、招聘类型、JD完整度为已加载页过滤；页面明确当前页数量和120条上限，不冒充全库或全网搜索。后续服务端分页/筛选是独立待增强项。
