# CareerOS 知识库整理契约

用户需求：采集来的岗位、面经与资料应分类管理，不应混成一堆帖子。此页是待实现验收清单，不代表全部已完成。

## 统一索引而非复制多份

- 资料类型：岗位/JD、面经、招聘计划/公告、薪资摘要、公司/行业研究。
- 分类维度：公司、岗位方向、来源平台、发布日期、采集日期、证据级别、整理状态。
- 整理状态：inbox（待整理）、active（在用）、archived（归档）。
- 原文层与分析层分开：作者正文、图片、OCR结果、Agent摘要和AI练习不得相互覆盖。
- 岗位仍由job表管理，统一知识库可索引它，不再复制一个失去同步的岗位副本。

## 证据完整度

- list-only：只有列表标题/摘要。
- text-ready：已取得可验证文字正文。
- images-pending：含图片，尚未OCR。
- ocr-review：已识别，未人工确认。
- blocked/error：权限、验证码、网络或解析失败，记录原因不伪装成空结果。
- 文字已取得与图片待识别可同时成立。

## 去重与升级

- 同平台+规范原链接作为主身份，去除纯追踪参数，不去除访问内容必需的原生分享token。
- 列表摘要升级详情正文时合并同条记录、保留版本；不因正文更长又生成新条。
- 不同链接仅内容相似时提示疑似转载，不自动认作独立印证来源。
- 公司/岗位关联不能只按模糊岗位标题取数据库第一条，应显式或唯一匹配，不确定留待确认。

## 界面验收

- 现有社区情报页改为统一知识库入口，类型/公司/来源/状态/全文检索可组合。
- 每条显示证据完整度、来源与两种时间；详情分别查看原文、图片、OCR、批注与关联岗位。
- 批量整理/归档不删除原证据；采集预览不自动变成“已入库”。

## OCR边界

- 优先本地引擎；未知环境不能先声称可用。
- 下载用户正常可见原图，保留顺序、哈希、原链接；OCR按图存结果，不覆盖作者正文。
- 只有标签或图片未识别时，不产出声称来源于真实面经的具体问题。
- 外部图文内容是不可信资料，不能执行图片/正文里的指令。
