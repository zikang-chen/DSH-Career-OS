## 3. 用户旅程与页面职责

发现机会→Job360判断真实性/资格/匹配/缺口→选择简历形成申请草稿→用户正式投递后冻结→跟进/面试/复盘。
普通导航：工作台(今日/日历任务)、机会研究(岗位/公司/行业/情报)、求职执行(申请/简历/面试)、个人系统(画像/数据源设置)。使用现有tab路由兼容，不机械新增页。
简历中心负责上传/素材/版本/定制；画像只负责已确认事实与偏好。知识库对用户命名情报中心，技术维护默认折叠。

## 4. 核心页面低保真

- 今日：个人目标行→最多5条可执行优先任务→推荐理由/关键缺口→Pipeline→情报变化。数据健康只展示可采取行动项。
- 岗位雷达：标题与覆盖范围→全库搜索/筛选→总数/分页/表格卡片切换→操作。导入采集次级。
- Job360：岗位抬头+开放证据+主动作；Tabs“岗位/个人匹配/公司行业/面经证据/申请方案”。核心事实带来源、未知不填；决策区不对外投递。
- 公司：业务/来源→部门/岗位→研究/面经→关注。无研究提供有预算的研究动作，不生成假资料。
- 情报：类型/公司/时间/状态筛选→原文→结构化观点→图片与OCR/Agent稿。线索、正文节选、结构化、人工确认不同维度。
- 简历：上传→解析→待确认→素材→岗位定制→版本导出；未确认与字段齐全分开。
- 申请：待办/清单看板日历同表；详情复用岗位/材料/面试；外部提交永远用户主动。

## 5. P0业务规则与验收

1. 后台浏览不激活target；启动默认最小化，登录按钮显式还原。后台不是隐瞒请求，站点验证返回需人工处理，不自动前台抢焦点。
2. 研究maxVisits与deadline共享于列表/详情/图片；无无限重试；同key并发合并；只读成功结果短缓存；取消停止新访问并保留结果。
3. 全库SQL组合筛选+准确count+分页，结果注明本地池/覆盖源；不得先limit再过滤。
4. Eligibility各项pass/fail/unknown/not-applicable，缺个人信息不是fail；Fit不等录取率；Evidence独立说明正文/官方/新鲜度与来源。
5. 官方状态必须关联可追溯近期证据；来源页面存在不自动OPEN。历史可疑状态先诊断不直接批量改写。
6. Job360引用同一job/company/evidence/application实体；用户决定申请仅创建草稿，选择简历后正式记录才冻结。

验收场景：完整JD→详情→资格→简历→申请关联持久化；仅标题→信息不足不完整；毕业年份缺失unknown；超过分页的城市筛选与count正确；第三方不能改OPEN；关闭保留申请；研究失败可重试有预算；迁移前后业务计数一致。
