# CareerOS 最新版使用指南

> 更新：2026-11-17。本页对应当前产品结构；旧教程的历史示例不代表所有平台始终可用。

## 1. 从哪里开始

打开 DSH 左侧的 **求职面板**。导航按任务分组：

| 分组 | 用途 |
|---|---|
| 总览 | 看待办、推荐机会与计划 |
| 找岗位 | 浏览岗位列表，查看公司和行业背景 |
| 我的投递 | 跟进投递、查看冻结材料、准备面试 |
| 我的材料 | 维护画像/真实经历、制作简历、整理知识库 |
| 设置 | 登录数据源、查看采集结果和系统状态 |

第一次使用先导入简历，核对解析出的事实，再补毕业年份、城市、目标岗位、可出勤时间。不要把演示画像当成自己的真实信息。

## 2. 浏览岗位与判断信息是否足够

进入 **找岗位 → 岗位列表**：

1. 搜公司、岗位或 JD 关键词。
2. 按城市、招聘类型、状态及 JD 完整度筛选。
3. 打开岗位，先看职责、要求、硬条件、截止日期和来源。
4. 在Job360展开 **个人匹配／公司与情报／申请准备**，查看Eligibility/Fit/Evidence和缺口；选择简历、渠道、行动日期保存申请草稿，也可只收藏。
5. 选择 **准备简历 / JD 面试准备 / 加入投递**。

卡片中的未知表示没有取得该字段，不代表没有要求。匹配分表示偏好匹配度，不是录用概率。

**v2范围边界**：关键词、城市、招聘类型、完整度等由本地全库组合筛选后分页，默认每页20条，展示全库total与本页数量；不是全网搜索。默认紧凑表格，可切卡片，窄屏优先卡片。历史OPEN但缺当前官方状态摘录会标“可能开放·待核验”，不会批量删除历史标签。

“添加岗位”在列表后默认折叠，可选择平台采集、粘贴 JD 或高级公开招聘页抓取。

## 3. 五站登录和采集

进入 **设置 → 数据源**，在组内选择具体平台的登录入口：

- BOSS直聘、前程无忧：岗位列表与 JD。
- 小红书：笔记、面经文字及图片证据。
- 牛客：讨论/面经链接及可见正文节选。
- OfferShow：校招计划，另有首页公开薪资摘要；不等于完整薪资库。

v2普通研究使用后台标签，不自动激活窗口；冷启动默认最小化，实际零闪烁未验证。只有用户主动登录/续期才还原窗口。研究受90秒/6次访问的协作预算约束，任务进度可见并可取消，超过界面等待上限会请求停止；不是浏览器/同步操作绝对硬终止。使用独立 Edge/Chrome profile 保存登录资料。重启会保留资料，但是否继续有效由站点决定；验证码和失效登录需要用户正常处理。默认遵循系统代理，不绕过会员或访问控制。

然后到 **我的材料 → 知识库 → 采集资料**：选择站点、关键词、数量上限；岗位平台可选校招/社招/实习。

先点击 **预览采集**，检查标题、JD、缺口和范围；确认后点击 **确认入库**。当前确认会按同条件重新采集，因此结果可能随站点更新，返回明细才是最终结果。预览不写岗位、笔记或时间线。

对话也可以这样说：

```text
在BOSS找产品经理实习，先预览，补前2条JD，不要直接入库。
搜索牛客上的腾讯产品面经，保留原帖链接，标出只有节选的资料。
调研某公司某岗位：先找JD候选，再找小红书和OfferShow相关资料，不确定的别混进结论。
```

常用工具：`career_site_capture`、`career_job_research`、`career_browser_login`。招聘类型参数为 `campus / social / intern`，没有明确证据归 unknown，不默认社招。关键词补“实习/校招”不是平台原生类型筛选，返回后仍须逐条过滤。

## 4. 知识库分类管理

类型包括 **岗位JD、面经经验、招聘公告、薪资线索、研究资料**。可按关键词、公司、平台、整理状态筛选。

- **待整理**：新收资料默认状态。
- **在用**：已整理、当前有用。
- **已归档**：不再常用，但保留证据。

打开详情查看来源、发布时间、获取时间、文字完整度和历史版本。在“整理公司、岗位方向与标签”中修改分类和个人批注；不覆盖作者原文。

只有摘要、正文节选、已取文字正文是不同状态。文字正文齐全也不表示图片已读完。同链接升级详情保留版本；历史数据可点“补建历史索引”，不会重置已有归档与OCR。

关联岗位的资料可直接返回岗位或准备简历。重复来源不等于独立来源印证。

## 5. 图片识别、错字修复与 Agent 看图

### 本地 OCR

小红书采集可勾选 **确认入库后自动本地识别图片**，每批最多5张。也可在资料详情逐张点击“本地识别”。Windows本地中文OCR不上传模型服务。

原图、哈希、原始识别文字独立保存。空结果/超长图/链接失效会记录原因，不冒充识别成功。现阶段超出引擎尺寸上限的长图会报错，不自动裁掉后半部分。

### Agent 读图校错

在图片详情选择“让Agent读图并校错”：

1. 选择接收任务的对话。
2. 阅读并确认图片会交给该会话的模型服务。
3. 点击发送，任务排队进入所选对话。
4. Agent 获取原图、实际看图、保存独立校对稿；无法辨认处应标注，不靠上下文编补。
5. 返回知识库刷新查看。

当前模型必须支持看图，并允许相关工具。会话不可用时界面保留复制指令作为兜底。**已按DSH真实接口契约实现并测试，但当前GUI实际发送/返回完整流程尚未人工验收。**

### 识别错了怎么改

对照原图直接编辑“核对文字”，点击保存。原始OCR、Agent稿和人工修订可追溯；默认展示最终人工修订。AI校对不等于人工确认，也不证明作者内容是真实面试题。

## 6. 从真实经历制作岗位简历

从岗位详情点“准备简历”，目标岗位会带入工作室，无需重新填写。经历从素材库选择、排序、精简；证书从个人资料库按相关性选择。

`career_resume_skill` 给XYZ/STAR/量化/关键词等诊断。缺数字就列待补，不编成果；参与不自动改成主导；研究投稿不改成录用。确认事实后生成版本，再检查质量并编译PDF。

## 7. 投递与面试

“加入投递”只建立收藏/准备记录，不实际发送简历。已有记录会定位该岗位投递，避免反复收藏。

- 草稿阶段可以换简历和资料。
- 首次正式标记已投递时，冻结最终JD、简历文本/LaTeX、资料字段与哈希。
- 已投后的原材料变化不覆盖历史；快照不是对原附件二进制已归档的承诺。

投递详情中继续查看岗位、准备草稿和面试。普通侧栏切页清旧岗位上下文；任务内跳转携带明确岗位。

“JD面试准备”是根据提供的JD生成练习方向，不承诺自动完成广泛调研；明确关联岗位的真实样本单列。AI练习、用户自述与官方要求不能混为一谈。

## 8. 已验证与限制

- 五站均做过真实搜索验证，BOSS/51job取过JD，小红书取过文字与图片，牛客取过正文节选。
- 51job有偶发渲染超时；牛客可能截断；OfferShow完整薪资库未承诺。
- 本地OCR真实图可运行，但会错字；视频内容未解析。
- v2当前全量离线回归422项通过；实际GUI亮/暗主题、窄屏和完整点击路径尚未验收，不能以代码测试替代。
