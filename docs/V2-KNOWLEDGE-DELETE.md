# 知识库删除能力（含连带删除来源与图片）

## 三种删除范围

在情报中心打开资料详情、点「删除资料」后，两次点击确认，并可按需勾选：

1. **只删知识库条目**（默认）：删除条目本身及其历史修订，留审计。
2. **同时删除关联来源**：
   - 来源是岗位 → 删除该岗位及其来源记录、状态历史、匹配结果、笔记；已有投递保留但解除岗位绑定。
   - 来源是面经原文（forum_post）→ 删除原文记录与其结构化观点。
3. **同时删除本机已下载的图片文件**：只删插件数据目录（`data/knowledge-media`）内的文件；目录外路径一律不动，并在结果里列出被保留的路径。

不勾选则来源与图片都保留——所以"删资料"和"删来源"是两件事，不会互相绑架。

## 岗位也可单独删除

岗位列表打开 Job360 后新增「删除岗位」，同样两次点击确认。走 `POST /jobs/delete`，与工具 `career_job_delete` 行为一致：删岗位+来源+状态历史+匹配+笔记，投递保留并解绑；**不会**自动删除知识库里对应条目（避免一次误操作连删两处）。

## 接口与工具

- `POST /knowledge/delete`：`{id, deleteSource, deleteMedia, reason}`；纯条目删除仍支持 `{ids:[...]}` 批量。
- `POST /jobs/delete`：`{id}` 或 `{ids:[...]}`。
- `career_knowledge action=delete`：必须 `confirm=true`；`deleteSource` / `deleteMedia` 只在单条时生效。

## 安全与留痕

- 删除前写 `sync_run`（kind=`knowledge_delete`）审计：标题、类型、平台、关联来源、原因、时间。
- 图片删除做路径收敛检查（`path.resolve` + 前缀匹配数据目录），越界路径不删、只报告。
- 工具层缺少 `confirm=true` 一律拒绝，不删任何东西。

## 验证

新增 6 项离线测试：连带删岗位、连带删面经原文与其观点、不勾选时保留来源、只删数据目录内图片、不勾选时保留图片、目录外路径不动。全量 **457 项通过**。

## 边界

- 硬删除无回收站；只想隐藏请用「归档资料」。
- 删除岗位不会级联删除知识库条目，反之亦然——这是刻意的，避免误删扩大。
- 已投递记录会保留但失去岗位绑定，历史材料快照不回收。
- GUI 实际点击与窄屏表现未验收。
