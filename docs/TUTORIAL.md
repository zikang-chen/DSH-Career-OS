# CareerOS 使用教程

> 面向使用者。按「想干什么」查，不按功能模块查。
> 所有命令既可以在对话里让 Agent 执行，也可以在面板上点。

---

## 0. 第一次用：5 分钟起步

### 0.1 打开面板

左侧边栏底部 → **🎯 求职面板**。九个页签：总览 / 计划 / 简历 / 资料库 / 岗位雷达 / 投递 / 公司行业 / 面试 / 设置。

### 0.2 填画像（必做，否则一切排序都没意义）

对话里说：

```
我是东南大学计算机硕士，2028 届，找 AI 产品实习，北京上海，每周能出勤 4 天
```

Agent 调 `career_profile_update` 写进去。或者面板「设置」里逐项填。

**为什么必须先做**：匹配排序、时间线推算、简历出稿全靠画像。画像空着，系统只会说「信息不足」。

### 0.3 导入简历

三种方式：

| 方式 | 操作 | 适用 |
| --- | --- | --- |
| 单份上传 | 面板「简历 → 上传」选文件，或对话里给路径 | 只有一两份 |
| **批量导入** | 对话：`把这目录下所有简历导入 D:\简历\` | **一堆旧版本/不同方向** |
| 直接粘文本 | 对话里粘简历正文 | 没有文件 |

支持 PDF / DOCX / MD / TXT。PDF 解析依赖已在项目内 `runtime/pylib`，新机器跑一次 `node scripts/setup-runtime.mjs`。

> ⚠️ 解析器只做初判。**学术型 CV 容易被读错**（比如把专业读成「客户关系」），
> 所以系统不会直接用解析结果覆盖画像——它会给你一份「候选」，你确认后才入库。

### 0.4 检查解析结果

面板「简历 → 素材库」看被拆成的经历条目。**每条都要点「确认属实」**，
未确认的条目在出稿时会被当作不存在的证据。

## 1. 找岗位：从「我要投腾讯」到拿到岗位表

### 1.1 一句话流程

```
你：我想投腾讯
    ↓
Agent 查内置清单 + 现场探测 → 给你能打开的校招地址
    ↓
你：在弹窗里登录一次（之后不用再登）
    ↓
你：在页面上选好筛选条件（批次/城市/岗位类别）
    ↓
Agent 从你打开的页面抓 → 岗位入库 + JD 快照 + 抓取留痕
```

### 1.2 具体操作

**第一步：要地址**

```
腾讯校招官网在哪
```

Agent 调 `career_campus_portal`，返回实测能打开的那个（如 `https://join.qq.com`）。

> 地址不靠记忆。系统内置 15 家公司的候选地址，每次**现场探测** HTTP 状态和页面标题，
> 只把真能打开的给你。清单外的公司会明确说「我不知道」，让你给一次确认过的地址。

**第二步：登录**

```
帮我登录腾讯校招
```

Agent 调 `career_browser_login`，弹出一个**独立的 Edge 窗口**。
在这个窗口里正常登录即可。

- 登录态存在 `data/browser-profile`，**关窗口、重启电脑都不丢**
- 这个 profile 与你日常用的 Edge 完全隔离，不会碰你的浏览记录和密码

**第三步：在页面上选好筛选**

这一步很关键。用页面自带的筛选器收窄范围，比如：

- 招聘类型 → **实习生**
- 城市 → 北京 / 上海
- 岗位类别 → 产品 / 运营 / 设计

等岗位列表**真的显示出来**，再回来告诉 Agent。

**第四步：抓**

```
抓一下腾讯的实习生岗位
```

Agent 调 `career_browser_capture`，参数里带上 `scope`（筛选范围描述）和 `recruitType`。

抓完你会看到：

| 字段 | 含义 |
| --- | --- |
| `found` / `parsed` | 接口返回多少条 / 解析成功多少条 |
| `created` / `merged` | 新建多少 / 合并到已有多少 |
| `diff` | 跟上次同范围抓取比：新增 / 下架 / 未变 |
| `jdSnapshotsSaved` | 存了多少条 JD 快照 |
| `freshness` | 上次什么时候抓的、什么时候过期 |

### 1.3 为什么「下架」有时报、有时不报

这是刻意设计：**只有「同一个筛选范围」且「有上一次基线」时才判定下架**。

上次看「全部」这次看「实习生」，消失的岗位不可能是下架——只是没筛进来。
这种情况下系统会说「无法可靠判定下架，本次已建立基线」，不给你一个假数字。

### 1.4 岗位列表会变，什么时候该重抓

```
腾讯的岗位什么时候过期
```

Agent 调 `career_capture_status`，返回 `ageDays / stale / dueAt`。
阈值 **7 天**：超过 7 天再抓，会自动做 diff，告诉你新增了什么、下架了什么、哪些 JD 改了要求。

### 1.5 抓不到怎么办（四条路，总有一条通）

| 情况 | 用什么 |
| --- | --- |
| 公司用 Lever / Greenhouse / Ashby / SmartRecruiters | `career_jobs_crawl` 直接抓公开 API |
| 大厂 SPA + 要登录 | `career_browser_login` → `career_browser_capture`（主力） |
| 不想开浏览器，只想粘一条命令 | `career_jobs_from_curl`（F12 → Copy as cURL） |
| 完全自动化不了 | 面板「新增岗位」粘 JD，或 `career_job_save` |

## 2. 看岗位详情

面板「岗位雷达」里：

- **单击或双击任意岗位卡片** → 弹出完整详情
- 详情包含：基本信息（编号/批次/地点/部门/学历要求/语言要求/薪酬/可转正…）、技能要求、匹配解释、岗位描述、来源证据、状态历史、备注
- 右上角「**去投递页**」直接打开官网申请页
- 底部可标记招聘状态（只有官方证据能改 OPEN/CLOSED）

> **如果岗位没有 JD 正文**：系统会明确告诉你原因（列表接口只返回标题和地点），
> 并让你去详情页看。不会拿一段编的 JD 糊弄你。

## 3. 挑岗位：匹配排序

```
我现在最该投哪几个
```

Agent 调 `career_match_rank`，按六维打分（硬条件 30 / 经验 20 / 兴趣 20 / 通勤 15 / 成长 10 / 新鲜度 5），分成：

- 高优先级申请
- 值得尝试
- 需要补强
- 暂不符合硬条件
- 信息不足，待研究

**分数是与你的偏好的匹配度，不是录用概率。** 别把它当成功率看。

想让某个岗位的分数解释清楚：`career_match_job {id}`，它会把「已满足 / 未满足 / 需核实」逐条列出。

## 4. 改简历：针对某个岗位出稿

### 4.1 一键出稿

```
针对这个岗位给我出一版简历
```

Agent 调 `career_resume_build {jobId}`，做四件事：

1. 按岗位关键词**挑选**该留哪几段经历
2. **排序**（产品岗把实操经历放前面，研究岗反过来）
3. **精简**要点（默认每段 3 条）
4. 从个人资料库按相关性挑证书，生成「证书与语言」小节

**只挑选和排序，不编造任何内容。**

### 4.2 强制包含 / 排除

```
这版一定要保留闲鱼那段，去掉实验室那段
```

参数 `includeIds` / `excludeIds`。

### 4.3 看缺口

出稿结果里 `gaps` 是真实缺口——岗位要求里有、你素材库里找不到的项。
**这些不会替你编**，是要你去补的。

### 4.4 编译成 PDF

```
把这版编译成 PDF
```

Agent 调 `career_resume_compile`，本机 xelatex 编译（实测 1 页约 2.7 秒）。
也可以到面板「简历 → LaTeX 工作室」直接改 LaTeX 源码再编译。

## 5. 投递管理：从投递到复盘

### 5.1 记录一次投递

```
我投了腾讯 AI 产品经理，用产品版简历，附了成绩单
```

Agent 调 `career_application_create`，它会：

- **冻结当时的 JD**（岗位以后被刷新或下架都不影响回放）
- 记录**材料快照**（哪版简历 + 哪些资料）
- 检查**冷冻期**（同公司 6 个月内重复投递会告警）

### 5.2 面板怎么用

「投递」页：

- **点任意一行** → 弹出投递详情：冻结的 JD、当时提交了什么、状态时间线
- **状态下拉**可直接改，旁边「推进 ›」一键进下一阶段
- 顶部有**转化漏斗**：投递→测评→一面→二面→终面→Offer 的到达数与阶段通过率
- 逾期或停滞超 14 天的行会**高亮**

### 5.3 复盘看漏斗，不看投了多少家

```
我的投递转化怎么样
```

Agent 调 `career_funnel`，告诉你：

- 各阶段到达人数与通过率
- **卡在哪一关**（流失最多的一跳）
- 分渠道转化对比
- 停滞超 14 天的记录

> 样本 <10 条时会明确提示「转化率不稳定，先攒样本」。
> 只统计真的投出去的（有投递日期或状态到过 applied）。

### 5.4 填网申表单不用手抄

```
给我网申信息卡
```

Agent 调 `career_apply_card`，把姓名/学历/在读起止/排名/语言成绩/求职意向/附件**按表单顺序摊平**，
一键复制粘到招聘系统。**缺的字段如实标空**，并告诉你去哪补。

## 6. 校招时间线

```
我现在算秋招什么阶段 / 接下来该干什么
```

Agent 调 `career_plan`：

- 按你的**毕业年份**推算（2028 届 → 秋招在 2027）
- 阶段：暑期实习网申 → 秋招提前批 → 正式批 → 补录 → 春招 → 毕业窗口
- 每段有窗口和倒计时
- 动作清单从「画像完成度 + 岗位池 + 在投数量 + 临近截止 + 逾期跟进」算出来

**窗口是行业常规节奏（经验值）**。公司级节点用 `career_event_add` 登记后会覆盖进去。

需要一份完整作战计划（结合前景、门槛、部门）：`career_plan_brief`。

## 7. 个人资料库：存「凭据」

岗位雷达里的「经历」说的是**我做过什么**，资料库存的是**我有什么凭据**：
学历学位、成绩单、四六级/托福、专利、获奖、实习证明。

```
把这些证明都存进资料库 D:\证书\
```

Agent 调 `career_doc_ingest`，自动分类 + 抽分（托福/雅思/四六级/GPA），
**一律标为未确认**，等你核对。

核对后点「确认属实」。资料库里确认过的凭据，出简历时才会进「证书与语言」。

> 图片型扫描件不做 OCR，只登记文件，字段需手工补。

## 8. 常见问题

**Q：为什么不能用 DSH 内置浏览器登录？**
内置浏览器是沙箱化 Electron `<webview>`，插件读不到它的页面和网络请求（bridge 只开放 `acquire/release/onOpenRequested`）。
所以系统另起一个独立浏览器进程，数据通路才通。

**Q：抓取会被封号吗？**
只读页面**自己发出**的请求，不构造请求、不破解签名、不绕过登录，一次一页串行。
比批量脚本温和得多。但仍建议只抓你真正要投的范围。

**Q：数据存在哪？**
全部在 `D:\career_os\data\`（SQLite + 简历原文 + 浏览器 profile）。不出本机。
`data/` 和 `runtime/` 不从进 Git。

**Q：岗位没有 JD 正文怎么办？**
有些站点的列表接口只返回标题和地点（如腾讯）。系统会如实说明，让你去详情页看。
不要指望它编一段 JD。

**Q：我能直接改数据库吗？**
可以，但建议走工具/面板——工具会同时更新索引、状态历史、匹配结果。
